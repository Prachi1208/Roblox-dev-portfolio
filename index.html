Cross-Server Teleportation

A fault-tolerant queue system that teleports groups of players to a separate game server. TeleportAsync fails silently in live production far more often than tutorials suggest, so the queue retries automatically, recovers cleanly if every attempt fails, and keeps the on-screen status in sync so no player is left stuck mid-teleport.

local function teleportQueue()
    canJoin = false
    statusLabel.Text = "Teleporting!"
    local attempts = 0
    local success = false

    repeat
        attempts += 1
        local ok, err = pcall(function()
            TeleportService:TeleportAsync(PLACE_ID, queue)
        end)
        if ok then
            success = true
        else
            warn("Attempt " .. attempts .. " failed: " .. tostring(err))
            task.wait(3)
        end
    until success or attempts >= 5

    if not success then
        warn("All teleport attempts failed.")
        statusLabel.Text = "Teleport Failed. Try again."
        task.wait(3)
        canJoin = true
        counting = false
        updateStatus()
        return
    end
end

TeleportAsync can fail for reasons outside your control, rate limits, unpublished places, server hiccups. This retries up to 5 times with a short backoff, and if every attempt fails, it fully resets queue state and the UI instead of leaving players stuck watching "Teleporting!" forever.

Orb Merge System

Players merge three matching orbs into the next tier of a 29-step progression chain. The merge function validates the player actually owns enough matching orbs, safely detaches any of them that were equipped before consuming them, grants the resulting orb, and re-equips it if the originals were in use, all in one atomic operation so an interrupted merge can never leave a player's inventory in a broken state.

function VisualFlexConfig.MergeOrbStacks(visuals, leftKey, rightKey)
    if type(visuals) ~= "table" then
        return false, "Orb inventory unavailable."
    end

    local createdKey = VisualFlexConfig.GetOrbFusionResultKey(leftKey, rightKey)
    if not createdKey then
        return false, "Choose three matching orbs of a non-max form."
    end

    visuals.OrbStacks = type(visuals.OrbStacks) == "table" and visuals.OrbStacks or {}
    local leftCount = VisualFlexConfig.GetOrbStackCount(visuals, leftKey)
    if leftCount < ORBS_PER_MERGE then
        return false, "Three matching orbs are required."
    end

    local equipped = visuals.Equipped and (visuals.Equipped.Orbs or visuals.Equipped.Cores or visuals.Equipped.Orbits) or {}
    local consumedEquipped = 0
    for index = #equipped, 1, -1 do
        if equipped[index] == leftKey and consumedEquipped < ORBS_PER_MERGE then
            table.remove(equipped, index)
            consumedEquipped += 1
        end
    end

    visuals.OrbStacks[leftKey] = leftCount - ORBS_PER_MERGE
    if visuals.OrbStacks[leftKey] <= 0 then
        visuals.OrbStacks[leftKey] = nil
    end

    createdKey = VisualFlexConfig.AddOrbStack(visuals, createdKey, nil, 1)
    if consumedEquipped > 0 and #equipped < VisualFlexConfig.GetCoreLimit(visuals) then
        table.insert(equipped, createdKey)
    end

    visuals.Equipped = type(visuals.Equipped) == "table" and visuals.Equipped or {}
    visuals.Equipped.Orbs = equipped
    visuals.Equipped.Cores = equipped
    visuals.Equipped.Orbits = equipped

    return true, createdKey, consumedEquipped
end

Runs entirely server-side so a client can never fake owning orbs it doesn't have. It checks the player holds at least 3 matching orbs before touching anything, removes exactly 3 (preferring ones that were equipped), grants the next tier via a shared merge-order lookup, and re-equips the result if the consumed orbs were in use, so a player's loadout never silently breaks mid-merge.

Prop Disguise System

Players can transform into any tagged prop in the world to hide from zombies. The trickiest part isn't the transformation itself, it's making the cloned prop sit correctly on uneven ground: the client raycasts downward every frame to find the floor beneath the player, then corrects the prop's position using its own bounding box so it never floats or clips through terrain, regardless of the prop's size or shape.

RunService.RenderStepped:Connect(function()
    if isTransformed and propClone then
        local rootPos = humanoidRootPart.Position

        local raycastParams = RaycastParams.new()
        raycastParams.FilterDescendantsInstances = { character, propClone }
        raycastParams.FilterType = Enum.RaycastFilterType.Exclude
        local rayResult = workspace:Raycast(rootPos, Vector3.new(0, -10, 0), raycastParams)
        local floorY = rayResult and rayResult.Position.Y or (rootPos.Y - 3)

        local finalCFrame = CFrame.new(rootPos.X, floorY, rootPos.Z) * snappedRotation
        propClone:SetPrimaryPartCFrame(finalCFrame)

        local propCF, propSize = propClone:GetBoundingBox()
        local propBottom = propCF.Position.Y - (propSize.Y / 2)
        local correction = floorY - propBottom
        propClone:SetPrimaryPartCFrame(finalCFrame + Vector3.new(0, correction, 0))
    end
end)

Runs every frame while a player is disguised: a downward raycast finds the floor, then a bounding-box correction snaps the prop flush to it. This keeps any prop, of any size, sitting correctly on stairs, slopes, and uneven terrain without per-item tuning.
